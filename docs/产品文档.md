# TVBox 源维护系统 · 产品文档 v1.0

> 状态：**已确认**（关键决策见 §12）
> 日期：2026-11-08

---

## 1. 一句话定位

一个**自动化维护 TVBox 配置源的工具**：从网上持续发现 TVBox 接口源，对每个源做"体检"（可达性、格式、内容规模、子资源健康），维护一份带健康分的源库，并发布成可直接导入 TVBox 的多仓订阅文件和榜单。

**不做什么**：不托管/不分发任何视频内容；不执行源里的 spider 代码；不做播放器。

## 2. 背景与现状

TVBox（及其分支：影视仓、OK 影视等）通过导入 JSON 配置文件来获得点播站点、直播、解析能力。生态现状：

- 源以"口口相传"的 URL 形式流通，失效极快（托管站跑路、jar 失效、站点被封）；
- GitHub 上已有不少聚合仓库（如 [25175/tvyuan](https://github.com/25175/tvyuan) 用 Actions 每小时聚合、[scovis/TVBox](https://github.com/scovis/TVBox)），但**多数只做"搬运"，不做持续的可用性验证与历史追踪**；
- 用户痛点：拿到一份多仓，导入后一半是死的，不知道该留哪个。

本项目的差异化：**以"体检 + 历史健康度"为核心**，而不是单纯的搬运聚合。

## 3. 名词说明

| 术语 | 含义 |
|---|---|
| 单仓 / 接口 | 一个 TVBox 配置 JSON，顶层含 `sites`（点播站点）、`parses`（解析）、`lives`（直播）、`spider`（爬虫 jar 路径）等字段 |
| 多仓 / storeHouse | 一种特殊配置，顶层是 `storeHouse: [{sourceName, sourceUrl}]`，即"仓库的仓库"，TVBox 里可切换子仓 |
| spider jar | `sites` 中 `type: 3` 的站点依赖的可执行 jar/dex，是**代码**，只能引用不能由我们执行 |
| 源（Source） | 本项目中一个被登记、跟踪的配置 URL |

配置顶层结构参考（已核实）：

```json
{
  "spider": "./jar/spider.jar;md5;xxxx",
  "sites":  [{ "key": "...", "name": "...", "type": 0|1|3, "api": "...", "searchable": 1 }],
  "parses": [{ "name": "...", "type": 0|1|3, "url": "...", "ext": {...} }],
  "flags":  ["youku", "qq", "iqiyi"],
  "lives":  [{ "name": "...", "type": 0, "url": "http://.../live.txt", "epg": "..." }],
  "storeHouse": [{ "sourceName": "仓库名", "sourceUrl": "http://.../xxx.json" }]
}
```

## 4. 目标用户与场景

- **主要用户**：你自己（TVBox 用户 + 想要一份长期可靠的源清单）。
- **场景 1**：每天/每周自动跑批，失效源自动标记，产出一份"当前可用"的多仓。
- **场景 2**：想找新源时，看榜单挑健康分高的导入。
- **场景 3**（可选）：把榜单/多仓发布出去给别人用（涉及合规，见 §10）。

## 5. 功能需求

### F1 源采集（Discovery）—— 优先级 P0（半自动起步）

| 项 | 说明 |
|---|---|
| 人工清单 | `config/sources.yaml` 手工维护种子源（M1 即可用） |
| 多仓递归展开 | 发现一个多仓后，自动登记其 `storeHouse` 子仓（**深度限制 2 层**，防止无限嵌套爆炸） |
| GitHub 发现（M2） | GitHub Search API 搜 `storeHouse`/`spider` 关键词与 topic:tvbox 的仓库，提取 raw JSON 链接 |
| 链接提取（M2） | 从已知聚合页/文章中用正则提取 `https?://...(\.json\|\.txt)` 候选，先入"候选池"，验证通过才转正 |
| 去重 | URL 规范化（去 utm、统一大小写敏感部分）后按 hash 去重；同内容不同 URL 视为镜像，可互为备份 |

### F2 源验证（Validation）—— 优先级 P0，本项目核心

验证分三级，默认档位【待确认 → §12 Q2】：

| 级别 | 做什么 | 产出 |
|---|---|---|
| **L1 可达** | HTTP GET（超时 10s、重试 2 次、全局限速）；大小上限 5MB；JSON/JSONP 解析；识别 schema 类型 | 状态码、耗时、是否合法 JSON |
| **L2 体检** | 解析 `sites/parses/lives` 计数与类型分布；对 `spider` jar、`lives[].url`、`wallpaper` 等**子资源**做 HTTP 探测（只测状态，不执行 jar） | 站点数、直播源数、jar 可用性、体检报告 |
| **L3 抽测**（可选开关） | 抽样请求 2-3 个 `type 0/1` 站点的 CMS 接口（`?ac=list`）；抽样 HEAD 直播流地址 | 站点真实可搜率、直播流可用率 |

判定规则（初版）：
- `active`：L1 通过 + JSON 含 sites/lives/storeHouse 任一；
- `flaky`：最近 N 次检查成功失败交替；
- `dead`：连续 3 次 L1 失败（404/超时/非 JSON）；
- `invalid`：可达但解析不出 TVBox 结构。

### F3 源库与历史（Registry）—— 优先级 P0

- SQLite 存储，字段见 §7；
- 每次检查存**内容快照**（gzip 压缩，保留最近 K 份），可对比"这个源改了什么"；
- 健康分：按"最近成功率 + 稳定性（抖动）+ 内容规模"加权，0-100；
- 人工标注：`starred`（置顶推荐）/ `banned`（永不收录）。

### F4 发布（Publish）—— 优先级 P0（已确认产物范围）

- `output/多仓.json`：storeHouse 格式，只收录健康分达标源，TVBox 一键导入；
- `output/报告.md`：榜单表格（名称/站点数/直播数/健康分/最近检查时间/状态）；
- （M3）静态网页：目录 + 单源详情页 + 历史可用率曲线，可挂 GitHub Pages；
- 不做本地 Web 管理台（管理动作全部走 CLI + `sources.yaml`）。

### F5 调度与运维（已确认：本地 CLI + GitHub Actions）

- CLI：`tvboxkeeper check` / `tvboxkeeper discover` / `tvboxkeeper publish` / `tvboxkeeper report`；
- **GitHub Actions 每日定时跑批**（L1+L2），跑完把 `output/` 与数据提交回仓库（仓库可私有），实现无人值守；
- L3 抽测默认关闭，仅本地手动低频触发；
- 电脑开着时也可用 Windows 计划任务兜底跑本地批次（可选）；
- 跑批结果变化时输出 diff 摘要（新增 x 个、失效 y 个），写入报告头部。

## 6. 处理流水线

```
发现(采集/递归/搜索) → 候选池 → 抓取 → 解析分类(单仓/多仓/无效)
  → 验证(L1/L2[/L3]) → 评分入库(SQLite+快照) → 发布(多仓/榜单/网页)
```

## 7. 数据模型（核心表）

```sql
CREATE TABLE source (
  id           TEXT PRIMARY KEY,      -- sha1(normalized_url) 前 16 位
  url          TEXT NOT NULL,
  name         TEXT,                  -- 自动取 sourceName/域名，可人工改
  schema_type  TEXT,                  -- tvbox | storehouse | mixed | unknown
  status       TEXT,                  -- new|active|flaky|dead|invalid|banned
  first_seen   TEXT, last_ok TEXT, last_checked TEXT,
  streak_ok    INTEGER DEFAULT 0, streak_fail INTEGER DEFAULT 0,
  latency_ms   INTEGER,
  sites_count  INTEGER, parses_count INTEGER, lives_count INTEGER,
  spider_md5   TEXT,
  health_score REAL,
  starred      INTEGER DEFAULT 0, banned INTEGER DEFAULT 0,
  notes        TEXT
);
CREATE TABLE check_log (   -- 每次检查一行
  source_id TEXT, ts TEXT, level TEXT, ok INTEGER,
  latency_ms INTEGER, detail TEXT
);
CREATE TABLE snapshot (    -- 内容快照（gzip），保留最近 K=10 份
  source_id TEXT, ts TEXT, content_md5 TEXT, gzip_path TEXT
);
CREATE TABLE origin (      -- 来源渠道
  source_id TEXT, channel TEXT, ref TEXT, ts TEXT   -- github|storehouse|manual|webpage
);
```

## 8. 技术方案

- **语言/栈**：Python 3.11+，`httpx`（异步 + 限速）、`SQLite`、`Typer` CLI、`pytest`；Windows 与 Linux 均可跑。
- **目录结构**：

```
TVBox源/
├── docs/                 # 本文档等
├── config/
│   ├── settings.yaml     # 超时/限速/阈值/验证档位
│   └── sources.yaml      # 人工种子源 + starred/banned
├── src/tvboxkeeper/
│   ├── discovery/        # 递归展开、GitHub 搜索、链接提取
│   ├── validate/         # L1/L2/L3
│   ├── registry/         # SQLite、快照、评分
│   ├── publish/          # 多仓 JSON、Markdown、站点
│   └── cli.py
├── data/                 # tvbox.sqlite + snapshots/（gitignore）
├── output/               # 发布产物
└── tests/
```

- **网络策略**：全局并发 ≤ 8、每站点 QPS 限速、随机 UA、失败退避；所有抓取内容视为**不可信数据**（只解析、不 eval、不上 shell）。

## 9. 里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M1 MVP** | CLI + 人工种子源 + L1/L2 验证 + SQLite + 多仓 JSON/Markdown 发布 | 导入生成的多仓到 TVBox 能看到健康源列表 |
| **M2** | 多仓递归发现 + GitHub 搜索 + 快照/健康分 + diff 报告 | 种子 10 个 → 自动扩到 100+ 源并持续跟踪 |
| **M3** | 定时调度（按 §12 Q3 结论）+ 静态网页 + 可选通知 | 无人值守跑一周，榜单自动更新 |

## 10. 合规与安全边界（红线）

1. **只存元数据与可达性结论**，不存储、不分发任何音视频内容；
2. **绝不执行** 源配置引用的 spider jar / dex —— 只下载测状态码并记录 hash；
3. 抓取的配置文件一律按**不可信数据**处理（隔离目录存放、纯 JSON 解析、禁止动态执行），这与本机安全规则一致；
4. 对目标站点限速、可配置 UA 与并发，避免对他人服务造成压力；
5. 提供 `banned` 名单机制，任何人可要求把某源移出发布产物；
6. 提醒：个人使用 TVBox 观看第三方源内容的版权合规性由使用者自负，本项目定位为"配置可达性监控工具"。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 源 URL 大量失效，榜单经常变 | 宽限期机制（连续 3 次失败才判死），镜像互备 |
| 多仓嵌套导致采集爆炸 | 递归深度 ≤ 2 + 总量上限 + 去重 |
| GitHub API 限流 | 用 token + 增量搜索 + 缓存 |
| 个别源是钓鱼/脏数据 | 候选池隔离，验证通过才转正；banned 机制 |

## 12. 已确认决策（2026-11-08）

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 项目定位 | **自用源库维护工具**（产物顺带可公开，不做导航站） |
| Q2 | 默认验证深度 | **L2 可达+体检**；L3 做成默认关闭的开关 |
| Q3 | 运行方式 | **本地 CLI + GitHub Actions 每日定时**，产物提交回仓库 |
| Q4 | 发布产物 | **多仓 JSON + Markdown 榜单**（P0），**静态网页**（M3）；不做 Web 管理台 |
| Q5 | 技术栈 | Python 3.11+（按建议采用，如有异议随时改） |
| Q6 | 直播源 | 跟随主源验证，L3 中留抽测能力，不单独深做 |
